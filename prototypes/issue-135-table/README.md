# 九席长桌 · 性能原型（issue #135）

一个**单文件、零构建、零外部资源**的 3D 原型，用来证明 #135 的视觉方向可以在
"静止时零绘制"的架构下成立。

它不是为了替代 `apps/client-vue`，而是为那个页面提供**可验证的渲染骨架**：
几何怎么合、灯怎么假、什么时候才绘制。

## 怎么打开

```text
直接双击 index.html
```

不需要 `npm install`，不需要 dev server。three.js 从 CDN 取（import map），
所以需要联网。若要用本地依赖，把 import map 的两条指向 `node_modules/three/...` 即可。

## 屏幕上你能证明什么

| 现象 | 说明 |
|---|---|
| 停留在画面上不动，`实际渲染` 不再增长、`跳过空帧` 持续增长 | 静止时不绘制，GPU 空闲 |
| 点任一阶段按钮，`实际渲染` 才开始增长，约 900 ms 后停止 | 镜头补间才绘制 |
| 点「按需渲染：关」，帧率读数变成持续满载 | 对照组：常驻渲染的代价一目了然 |
| 点「随机一人出局」，一盏灯灭，`draw calls` 不变 | 状态变化不重建场景 |
| `光源` 恒为 `2 / ≤2` | 没有任何 PointLight |
| 拖动窗口改大小，`缩放事件` 才 +1 | 只有 resize 才重建 drawing buffer |

## 预期读数

| 指标 | 预期 | 说明 |
|---|---|---|
| draw calls | **9–12** | 桌子 1、椅子 1（InstancedMesh）、灯笼 1、灯杆 1、光晕 1、地面 1、接触阴影 1、森林 2 |
| triangles | **≈ 3.5k** | 全是低模 + 实例化 |
| 实时光源 | **2** | 半球光 + 平行光，均不投影 |
| 阴影贴图 | **0** | 阴影烘进贴图与接触阴影贴片 |
| 静止时渲染 | **0 帧/秒** | 按需渲染 |

对照当前线上实现（`forest-cabin.html` + iframe）：约 15 个点光源、220+ 独立
mesh、每阶段 `setSize`、常驻 60 fps 渲染。加起来差了两个数量级。

## 与 #135 的对应关系

| #135 要求 | 本原型 |
|---|---|
| §1.3 不用 iframe | 直接一个 `<canvas>` |
| §3 九席长桌、暮色森林、雾气 | 程序化长桌/九椅/树影/雾 |
| §4.4 受限环视、可聚焦 | 四个预设机位 + 900 ms 补间 |
| §4.5 昼夜分级 | `PALETTE` 四个阶段，改颜色与强度 |
| 死亡座位灯灭 | 光晕顶点色置零，draw call 不变 |
| §4.7 性能预算 | 2 光源 / 0 阴影 / 9 draw call / 3.5k 三角 |

**没有实现**：真正的 HUD、投票、身份卡、护盾视觉、音频。这些留在 Vue 层，
本原型只负责"世界"。

## 已知取舍

- 桌面的暖光、接触阴影、森林明暗都是**烘进贴图**的，所以不能随光源移动而变；
  对本场景（镜头锁死、灯不动）不是问题。
- 光晕用 `Points` + 加性混合，因此**没有真实的体积光**；近看不如 Bloom 柔和。
  如果最终需要 Bloom，应在 high 档单独开半分辨率 pass，而不是恢复点光源。
- 灯笼的"照亮桌面"是贴图假象，所以**把灯挪位置就不成立**——它本来就是不动的。
