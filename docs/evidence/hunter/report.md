# 猎人专项联调报告（#77）

## 结论与根因边界

原通用触发 WAV 约 25.27 秒，而猎人窗口仅 30 秒；客户端逐帧实时发送且每帧等待存在计时开销，构成明确的客户端时间预算缺陷。原失败报告没有输入/STT 时间，无法追溯确认那一次是否还叠加平台或网络延迟，因此不将平台内部原因写成确定事实。

改为通用 2.8595 秒、猎人 3.626125 秒音频，窗口保持 30 秒。事件发布后立即调度，自己的私密状态提供技能上下文。就绪场景从窗口事件到调度选中约 1 毫秒。3.626 秒音频在第一次真实测试中实际发送约 5.589 秒，STT 在发送结束后约 0.451 秒到达；发送计时开销仍存在，但本批不扩大到协议节奏重构或跨回合复用。

## 全部六次尝试

2026-10-25 北京时间 00:05–00:09，使用已激活真实软件身份及既有 Agent，没有控制台拨打或手工 Session 绑定。其他座位由领域夹具操作，不是完整纯灵矽局，也不是真人语音验收。

| --- | --- | --- |

真实业务写入共五次，均有请求/行动/事件关联。两次输入失败属于测试注入，最后一项不计平台行动成功；迟到请求为手工 HTTP 探针，不是平台调用。定向开枪音频为“查私密状态，调用开枪工具打三号”，验证工具能力，不证明 AI 自主目标策略。三次猎人真实技能成功均在窗口内，不能据此承诺长期成功率。

六次场景均完成控制器释放与绑定清理；真实行动后可见客户端 closed 时间记录。主动关闭未结束的 TTS 会产生 input_failure/ACTION_INTERRUPTED_OR_TIMEOUT，此时已经接受的业务行动仍成功，不能重复计算为业务失败。第一轮诊断曾重复记录 accepted（没有重复写入），本 PR 已去重。

## 可重复运行

1. 确保独立 API 5100、MCP 9191 空闲，保留指向 9191 的测试隧道；不要占用正式实例端口。
2. 使用独立环境文件和已激活 player-a，测试 Agent 已绑定对应 MCP 和认证。无需改当前玩家身份；建议同步仓库玩家提示词。
3. 运行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/linx-audio.ps1 -OutputDirectory <仓库外音频目录> -IncludeHunterTest`。该参数仅额外生成定向测试音频，不作为正式默认输入。
4. 设置 `LINX_TURN_WAV` 和 `LINX_HUNTER_WAV` 指向短音频，运行 `node --env-file=<独立配置文件> scripts/linx-hunter-lab.mjs ready`。另运行 `reconnect`、`retry`、`timeout`。
5. 开枪专项把 `LINX_HUNTER_WAV` 临时设为 `hunter-shoot.wav`，运行 ready；完成后恢复 hunter.wav。每次运行创建新房间，通过合法夜间行动触发死亡，不提供生产跳阶段接口。
6. 脱敏结果自动保存在本机 LinxNight-lab/evidence。脚本结束关闭测试 API/MCP 和玩家连接。浏览器无需参与本专项；平台控制台截图未收集。
